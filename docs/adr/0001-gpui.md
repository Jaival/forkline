# ADR 0001: Replace Tauri + React with GPUI

Date: 2026-11-06. Status: accepted.

## Context

Phase 1 shipped Forkline as Tauri 2 + React on WebView2. Budgets pass on fake
data, but WebView2 costs about 430 ms before the page starts, which no app code
can change, and the UI is a second language and toolchain (Bun, TypeScript,
generated bindings) next to the Rust backend.

GPUI (Zed's UI framework) renders on the GPU in the same Rust process.
gpui-component (longbridge) supplies inputs, lists, tables, tabs, dock, menus,
notifications, a markdown `TextView`, a tree-sitter highlighter and a
virtualized split/unified `Diff` with annotations.

## Decision

- The UI is one GPUI crate, `crates/fl-app` (binary `forkline`). It calls the
  backend crates directly; no IPC layer, no generated bindings.
- Keep `fl-types`, `fl-db`, `fl-sync`, `fl-git`, `fl-search`, `fl-fake` and
  `fl-bench`, and their schema and migrations.
- Pin gpui exactly to the snapshot gpui-component is built against. gpui-component
  0.9.0 uses `gpui = { package = "gpui-pre", version = "=0.3.11" }`. Bump both
  together, never one alone.
- Prefer gpui-component's markdown, highlighter and diff; extend them through
  their plugin / render hooks before writing our own.
- Auth order: `FORKLINE_GITHUB_TOKEN` (dev), then a token the user saved in
  Windows Credential Manager (a pasted fine-grained PAT), then `gh auth token`.
  A saved PAT comes before `gh` so that pasting one actually takes effect.
  The OAuth device flow is removed with the Tauri app, which still uses it.
- Git stays on the `git` CLI. Add `gix` for reads only if the bench shows diffs
  are too slow.
- Budgets: launch from process start to Inbox painted < 600 ms, Forkline's own
  startup (GPUI ready to Inbox painted) < 60 ms, open cached item < 30 ms, tab
  switch < 8 ms, search p95 < 30 ms, 10k-line diff scroll 120 fps, 0 ms
  network wait on optimistic actions.
- Launch was first set at 200 ms. GPUI's Windows platform start (DirectWrite,
  DXGI and D3D11 device, run one after the other) takes about 330 ms on the
  reference machine before any app code runs. Patching GPUI to overlap them
  saves at most about 150 ms and means vendoring and re-patching
  `gpui-pre-windows` on every upgrade, so we keep stock GPUI and budget the
  part Forkline controls separately. The Tauri app took about 630 ms.
- 2026-11-16: launch raised from 450 to 600 ms and measured to Inbox painted
  (the launch view). Warm runs take 410-560 ms, of which about 450 ms pass
  before GPUI calls Forkline code; 450 failed on platform start alone.
  `app_startup_ms` (< 60 ms) stays the gate on Forkline's own code.
- Fake data: 50 repos, 20,000 issues and PRs, 100,000 comments, and 5 PRs with
  real diffs (one with a 10,000-line file).
- New in scope: Explore view, syntax highlighting in diffs and code blocks,
  stack splitter (last phase).
- Work happens on branch `gpui`. The Tauri app (`app/`, `ui/`) stays until the
  GPUI app reaches parity, then it is deleted.

## Consequences

- Bun, React, Vite, Tailwind, TanStack, Vitest, specta and tauri-specta leave
  the stack. `bun run check` becomes `cargo clippy --workspace --all-targets
  -- -D warnings` + `cargo test --workspace`.
- GPUI's API changes between snapshots; agents read the pinned source, not
  memory.
- If a GPUI limit blocks a feature (text input, IME, accessibility, markdown,
  drag and drop), stop and report options. Do not switch frameworks silently.
